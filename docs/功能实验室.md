## 一、工程职责 <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

| 目录 | 职责 |
| --- | --- |
| `../lib/main.dart` | 只初始化设置和启动 App |
| `../lib/demo_hub/` | 开屏、分组目录、搜索、收藏、最近使用、功能注册 |
| `../lib/demos/中文功能名/` | 每个功能完整集中管理；单文件优先，多个文件也留在本目录 |
| `../JobsByPubs/JobsDemoFoundationByPub/` | 独立预览壳、十语词库、主题、手势菜单和空态 |
| `../JobsByPubs/JobsLabRuntimeByPub/` | 命名空间存储、白名单桥接、加密／校验、对象记录、多任务计时 |
| `../JobsByPubs/JobsPlatformLabByPub/` | iOS／Android 原生设备、媒体、Runtime 与引擎桥接 |
| `../lib/JobsDemoTools/` | 旧路径兼容导出；实际 Demo 与专属依赖已集中到中文目录 |

开屏使用替换导航并取消计时器，返回不会再次看到开屏。首页搜索时只呈现历史或结果，取消恢复目录；搜索中禁用抽屉手势。收藏、最近使用、搜索历史、菜单宽度及外观设置持久化。界面复用 Material 和原生 iconfont 素材，资源有本地来源记录。远程图片示例先显示打包资源，异步加载失败时保留本地兜底。

## 二、运行与新增功能 <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

在项目根目录使用 Flutter `3.50.0` / Dart `3.14.0`，执行 `flutter pub get`。官方稳定版依据：[发布说明](https://docs.flutter.dev/release/release-notes)。FVM 两份版本配置和 CI 使用同一基线。

```shell
flutter run -t lib/main.dart
flutter run -t lib/demos/异形按钮/异形按钮.dart
flutter test
flutter analyze --no-fatal-infos
flutter build ios --simulator --debug
```

VS Code 的“运行当前 Demo 文件”使用当前文件作为入口；每个可运行文件提供顶层 `main()`。新增页面同时加入一个注册目录，填写唯一 ID、中文功能名称、分组、关键词、源码相对路径及 WidgetBuilder。主 App 直接 push 页面；独立文件由 `JobsDemoApp` 包裹。具有 GetX、Provider 等依赖的旧例子由局部运行适配器初始化依赖和路由；旧 main 的 runApp 在作用域内捕获，不替换主 App，退出时释放计时器、监听和连接。

独立运行可使用预览壳的“演示设置”切换十语和三主题。主 App 在全局设置切换。旧 Demo 的操作按钮、输入提示和状态词已接入实际十语，语言与主题保持响应式；代码名、教学数据和控制台输出保留原教学含义。藏语业务词库由项目提供；Flutter 未内置藏语的系统 Material／Cupertino 控件使用英语回退。

## 三、API 与离线回退 <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

首页立即绘制随包完整目录，同时 GET `api/demos`；成功响应形如 `{"ids":["calendar","handwriting"]}` 用于排序，只识别本地已经注册的功能，不能远程注入 Dart 页面，也不会删除原有功能。每次重新加载都会正常请求。偏好写入先在本地生效，再 PUT `api/demo-preferences/{key}`，JSON 为 `{"value":...}`。后续操作继续尝试服务端，不锁死到离线模式。

默认基址为 `http://localhost:8080/`，超时 900ms，失败／超时／解析失败保留本地目录及可演示操作。本工程不包含该服务端；这不是后台服务已部署的声明。用 `--dart-define=DEMO_API_BASE=https://example.com/` 指定实际服务地址；手机上的 localhost 指手机自身，连接开发机须传入设备可访问地址。Web 跨域和平台网络策略按实际部署配置，不为演示全局放开安全限制。

无服务器时直接运行即为离线预览。空列表提供完整占位和重新加载；无结果提供清空搜索；图片先用本地打包资源，指定网络图片失败时保留本地兜底；图标页另可观测实际内存／磁盘缓存和取消行为。旧网络与微应用示例同样采用短超时／本地回退，硬件入口按真实权限与支持状态反馈。

## 四、验证边界 <a href="#前言">🔼</a> <a href="#🔚">🔽</a>

`../test/demo_hub_test.dart` 覆盖开屏替换、搜索空态恢复、菜单宽度、收藏空态、十语三主题以及 API 失败后恢复。已有形状按钮的回归测试直接引用保留后的功能文件。

最新 SDK 对内置 `material.dart`／`cupertino.dart` 提供弃用提示。项目仍有 GetX 及大量历史组件使用这些类型，当前保持一致的类型体系；独立包迁移必须协调依赖，不能仅替换新文件 import 造成 Theme／Navigator 类型分裂。依据：[官方迁移说明](https://docs.flutter.dev/release/breaking-changes/material-ui-and-cupertino-ui)。弃用信息与编译错误分开记录，不修改第三方及生成文件消除信息。

原生蓝本有 ARKit、蓝牙、直播、Widget、动态 App 图标等能力。它们需要插件、原生宿主和设备验证；完整进度以[逐项对照](./原生功能对照.md)为准，普通交互替代页不算硬件能力已经平移。

2026-11-14 验证基线：**281 个目录入口**，主工程 **545 项**、公共菜单 **5 项**测试通过，分析无 error／warning。完整 Web JavaScript、Android APK、iOS Simulator 与 iOS 真机 arm64（无签名）构建分别验证；iOS 模拟器已安装启动，原生宿主 → 独立 Flutter 引擎 → 插件读写 → 回传 → 引擎销毁的实际往返也已完成。原生清单的 385 条注册记录对应 245 个独立目标类型，均提供实际功能路由和原始来源；详见[原生功能对照](./原生功能对照.md)。

CI 锁定同一 SDK，运行全部测试、公共组件与功能源码分析、Web 和 iOS Simulator 构建。首次依赖安装需要访问官方源；本机下载校验与构建日志位于忽略的 `.codex/verification/parity/`，不作为 App 的运行依赖。Android 保持 AGP 9.3.1／Gradle 9.5，宿主兼容旧插件的 jcenter 声明与 ProGuard 文件名，并统一库 compileSdk；不修改第三方插件源码。

原生设备能力的使用条件和未连接实体硬件的验证范围在对照文档分别记录。真机签名部署需要配置宿主／Widget 的一致 App Group；Unity 仅嵌入 iphoneos 的 arm64 Framework。
